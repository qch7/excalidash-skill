# 架构图设计

## 先选视图

明确图要回答的问题、读者和范围。区分系统结构、运行流程与部署视图。处理步骤放在所属组件边界内，并标注内部处理步骤；部署关系只在输入提供时绘制。标题说明主题与视图，例如企业知识问答 · 处理流程。

整理对象、动作、方向、边界和关键异常，选择一条主阅读路径。把长配置和原理说明放入配套文档。读图必需的条件放在对应路径附近。

## 按信息选形式

| 信息 | 视觉表达 |
| --- | --- |
| 归属或信任边界 | 有标题的浅色分区、泳道、局部嵌套 |
| 请求与数据处理 | 同向主流程，箭头标注动作或传递物 |
| 条件、并行与汇合 | 菱形、分叉与汇合，条件紧邻分支 |
| 存储、缓存与队列 | 一致的角色符号，连接标注读写或投递动作 |
| 时序、回调与异常 | 简化时序、回路或局部侧支 |
| 组件内部机制 | 所属边界内的步骤条或局部展开 |
| 真实指标与方案差异 | 带来源和单位的图表、紧凑比较表 |

形式由已有信息决定。保留未知细节的抽象标签；关键关系缺失时询问用户。绘制能力清单前，先区分独立组件、处理步骤和属性。属性使用短注释，执行顺序需要输入依据。

## 文字

- 节点使用一个名称和一行必要说明；条件与约束就近放置。
- 连线使用短动作、传递物或条件，例如查询答案、文本块、未命中。
- 用直接陈述，句子简短。删除转折句、口号、修饰词堆叠与近义词并列。
- 名称直接书写，不用引号强调名词。保留代码、标识符和原文引用需要的语法。
- 多处重复的角色可在分组标题中统一说明。标签过长时拆分内容或增加留白，保持字号可读。

## 布局与走线

1. 先放边界与主链路，再放存储、异常分支和辅助关系。在线与离线等不同语义可分区展示。
2. 使用少量固定行列、统一基线与间距。同类节点协调尺寸与内边距；按内容调整宽度。并列分支围绕主轴平衡展开，真实关系决定对称程度。
3. 为标题、标签和连线留空间。区域边界淡于主节点，标题带保持独立，避免用大边界装正文。
4. 按连接顺序排列同层节点。为查询、主流程、异常与观测关系选择清楚的起止端口，预留水平或垂直通道。
5. 优先直线或少折返的直角线。交叉出现时依次尝试换节点顺序、换端口、换通道与外围绕行。并行线路保持间隔，连接点只用于真实汇合。
6. 跨区长线影响阅读时，可拆为明确命名的关联视图。同一对象在不同视图中重复出现，须使用相同名称或编号，并说明对应关系。关系含义和方向必须完整保留。

主流程、异常和辅助关系采用稳定的线型与颜色，并给出小图例。图形含义同时由名称、形状或标签支持。共享总线仅用于真实共享关系。布局约束只调整位置，业务连线只表达真实依赖。

图标帮助识别角色，名称保持可见。原生 Excalidraw 存储圆柱可由矩形、椭圆和轮廓组合并分组；元素类型使用实际支持的类型。风格沿用用户要求和已有画板。

布局来源与工具限制见 [github-design-lessons.md](github-design-lessons.md)。

## 查看实际场景

用已保存的原生 elements 生成预览，保持坐标、尺寸、文字、绘制顺序和线路一致。说明近似渲染与网页的字体、线条差异。

逐项检查：

- 仅凭名称和箭头，能否读出主路径、分支条件与边界？
- 组件、内部步骤、读写方向和异常处理是否符合输入？
- 同层是否对齐，分支是否平衡，区域之间是否有适当留白？
- 是否存在交叉、共线覆盖、穿字、穿无关节点或含糊端点？
- 文字是否简洁，字号是否可读，标签是否溢出或重复？
- 核心内容是否为原生可编辑元素，预览是否来自同一场景？

先修正发现的问题，再保存。分别验证远端数据与视觉结果，报告实际检查范围。
